# 同类产品研究与独立实现边界

## 1. 文档目的

本项目可以研究战术篮球、球队经理模拟与数字战术板产品解决了什么问题，但研究结果必须转化为自己的规则、信息架构、视觉语言与参数体系。竞品仅用于识别通用交互习惯、系统拆分方法和常见失败点，不作为界面、文案、素材或数值的复制来源。

本文不是法律意见。涉及授权范围、可识别人物、商标、数据库、素材或产品表达的最终判断，以权利方书面许可、发行平台要求及专业审核结论为准。

## 2. 可借鉴的系统层经验

### 2.1 战术篮球类

- 把一个回合拆成可追踪的状态机：发球、推进、落位、战术发起、优势形成、终结、篮板或球权转换。
- 将“玩家选择”和“系统结算”分离。按钮只提交意图，结算器再读取当前持球人、实际对位、防守覆盖、协防到位、体能与比赛环境。
- 传球分为“选择接球队友”和“执行传球”两步；篮球智商影响选择质量，传球与控球影响球能否安全到达。
- 挡拆应有完整链路：掩护接触、持球人利用方向、防守覆盖、是否换防、掩护人下顺或外弹、二次传球窗口及残局对位。
- 防守不是单一减益。外线出手读取当前实际对位者的外防；突破先读取点防守，再读取真正及时到位的内线协防、内防与盖帽。
- 用固定随机种子、事件日志和逐步可重放的结算，保证同一输入可以复现，便于平衡和缺陷定位。

### 2.2 经理模拟类

- 日历、赛程、训练、成长、衰退、默契、伤病风险、合同与荣誉应作为相互独立的模块，通过明确的赛季事件连接。
- 模拟统计需要先定义合理区间，再由球员角色、上场时间、节奏、使用率与对手强度共同生成，避免只靠综合能力值线性放大。
- 成长与衰退采用“小步、有限频次、可解释”的变化：记录训练来源、年龄曲线、长期未训练惩罚和属性上限。
- 玩家实战数据可以参与下一场模拟校准，但应设置样本权重与上限，避免一场异常表现永久污染赛季数据。
- 季后赛、附加赛、奖项和退役采用数据驱动规则表，不把赛制写死在界面组件中。

### 2.3 数字战术板类

- 球场是主要信息面，棋子、球、跑位线、对位线与落点必须比装饰更醒目。
- 操作区使用稳定位置和上下文标签；相同手势在不同球权状态下必须有清楚、可预期的含义。
- 一次只强调当前可行动作。不可用动作提供原因，不静默降级成另一个动作。
- 对双击手势设置有限时间窗，并提供防误触与单击延迟处理；空接、扣篮等双击规则在玩法说明中集中解释。
- 每次结算同时给出“发生了什么”和“为什么”：例如“换防形成—内线球员被拉到外线”，方便玩家学习战术。
- 移动端优先保证触控热区、横屏安全区、色弱可辨识度、字号和号码可读性。

## 3. 本项目的独立转化原则

| 研究到的通用问题 | 本项目独立实现方式 | 禁止直接带入的内容 |
| --- | --- | --- |
| 如何表达十名球员位置 | 纸质战术板风格圆形棋子、原创小球衣轮廓和清晰号码 | 竞品棋子造型、线条样式、图标组合与布局比例 |
| 如何组织进攻选择 | 右侧五键上下文操作栏，动作由球权状态切换 | 竞品按键文案组合、菜单层级、图标和动画节奏 |
| 如何结算挡拆 | 自有状态机、实际对位更新、下顺/外弹效用函数 | 竞品公式、隐藏阈值、徽章名称和反馈文案 |
| 如何生成球员能力 | 自有 38 项定义、证据分层、原创权重与校准区间 | 逐项抄录、近似搬运或批量映射竞品精确数值 |
| 如何模拟赛季数据 | 角色、时间、节奏、使用率及对手强度模型 | 竞品数据库结构、赛季算法、排行展示和专有术语 |
| 如何教学 | 原创三分钟决胜节、逐步解锁动作和结果解释 | 竞品教程脚本、关卡结构、对白与引导遮罩 |

## 4. 不得复刻的内容

- 页面构图、组件尺寸、按键位置关系、专有交互流程或整体视觉观感的实质性复刻。
- 产品名称、模式名、徽章名、技能名、提示语、解说词、教程文本或其他可识别表达。
- Logo、球衣图案、官方标识、字体、照片、头像、音效、音乐、动画、模型或图标素材。
- 从截图、视频、内存、接口或数据文件提取的竞品参数、公式、阈值、球员数值或数据库字段。
- 将竞品精确数值做统一加减、轻微扰动或换字段名后继续使用；这种处理不构成独立的数据来源。

## 5. 数值与玩法的独立研发流程

1. 先写清每个属性的游戏内含义、输入和影响范围，再收集被允许使用的证据。
2. 将证据分为官方统计、公开比赛表现、内部观察、授权数据和纯设计参数，不把来源混为一谈。
3. 用原创公式生成第一版区间，并保留来源、版本、推演理由与修改记录。
4. 通过固定种子批量模拟，检查命中率、失误率、篮板率、犯规率、回合数及位置差异是否落在目标区间。
5. 由篮球设计审核“是否像该类型球员”，由权利审核确认“数据和命名能否发行”。
6. 任何来源或公式变更都重新跑回归测试，不直接覆盖已发布数值而不留版本记录。

## 6. 工程门禁

进入可发布构建前必须同时满足：

- 研究资料只存在于受限的研究目录，不打包进客户端。
- 每项外部数据和素材都能在权利台账中追溯到来源、许可文件、适用平台、地区、期限和限制。
- 竞品精确球员数值没有书面单独许可时，构建检查必须阻止其进入仓库与发行包。
- 运行时不存在未批准的联盟字样、Logo、球队 Logo、官方球衣图案、竞品名称或竞品专有术语。
- 界面、玩法文案、图标、音频和动效通过独立表达检查；高相似项必须替换或提交复核。
- 属性模型通过固定种子回归、边界值测试、对位更新测试和统计区间测试。
- 发布候选包保存台账快照、数据版本、测试报告和审核人记录，以便后续审计与撤回。

## 7. 验收证据清单

- 研究摘要与“研究点 → 原创方案”映射表。
- 玩法状态机、结算公式说明及版本号。
- 关键界面的来源图、实现截图和差异审查记录。
- 数值生成脚本或规则表、固定种子模拟结果与异常清单。
- 权利台账导出、许可文件索引及构建扫描结果。
- 文案、素材、字体、音频和数据的最终替换/批准记录。
