# 软件与制作工具

## 当前原型

| 领域 | 选择 | 原因 | 当前状态 |
|---|---|---|---|
| 界面 | React 19 + TypeScript | 组件化、可快速做状态原型、类型约束比赛事件 | 已使用 |
| 构建 | Vite | 本地启动快，适合高频小任务与热更新 | 已使用 |
| 战术板 | HTML/CSS + SVG 路线层 | 棋子适合 DOM 触控；路线适合 SVG；可分别做命中区和动画 | 已使用 |
| 图标 | Phosphor Icons | 统一线性图标，避免用字符或手绘近似资源 | 已使用 |
| 规则测试 | Vitest | 纯 TypeScript 状态机可快速固定种子回归 | 已使用 |
| 浏览器验收 | Playwright | 可自动测触控几何、弹窗、双击和双设备截图 | 已使用；测试脚本在仓库内，临时截图/录像留在仓库外 |
| 数据边界 | TypeScript + 运行时校验器 | 保证 38 项恰好齐全且都是 25..99 整数 | 已用于合成数据；正式外部数据包后续再加 JSON Schema/Zod |
| 视觉资产 | 原创生成的纸张球场 | 保持纸张战术板风格，不使用官方球场或标志 | 已使用 |
| 包管理 | npm + lockfile | 安装结果可重现 | 已使用 |

## 移动发行阶段

| 领域 | 选择 | 使用时机 |
|---|---|---|
| 移动容器 | Capacitor | M9，把已验证的网页逻辑封装为 Android/iOS 工程 |
| Android | Android Studio、Gradle、Android Profiler | 横屏锁定、签名、真机帧率、内存与后台恢复 |
| iOS | Xcode、Instruments | 必须在 macOS 完成签名、真机安全区和发布验证 |
| 本地存档 | IndexedDB 原型；正式版 Capacitor SQLite | 日历、阵容和赛季进入后启用 Repository 抽象 |
| 数据校验 | JSON Schema 或 Zod | 38 项属性、名单、赛程和授权元数据导入时启用 |
| 长模拟 | Web Worker | 30 队赛季批量模拟，避免阻塞比赛动画 |
| 无障碍 | axe + 屏幕阅读器人工测试 | 每个功能里程碑及 M9 真机门禁 |

## 架构边界

```text
src/game        纯规则、概率、随机种子、状态机
src/Prototype.tsx   界面编排，只发送语义动作
src/content     后续拆分 demo 与 licensed 内容包
src/platform    后续接入存档、声音、震动、移动生命周期
```

规则引擎不能读取浏览器时间、动画帧或 `Math.random()`；界面不能直接修改比分和统计。所有可复盘结果都由带版本号、随机种子和事件 ID 的领域事件产生。

## 连接不稳定时的工作流程

为避免长连接中断导致返工，开发按小检查点执行：

1. 只修改一个可独立验收的子问题。
2. 立即运行相关最小测试。
3. 通过后同步到 `D:\我能打职业`。
4. 每完成一个视觉状态保存独立截图。
5. 最后再跑生产构建和全量门禁。

代理或网络异常不会作为游戏运行依赖；正式游戏的核心比赛、日历和存档均按离线优先设计。
