# M6B-2 七局四胜季后赛与冠军闭环规则决策（冻结）

日期：2026-09-03
范围：首轮、分区半决赛、分区决赛、总决赛；不包含跨赛季年龄、退役与下一赛季。

## 1. 依据与产品边界

- 官方公开赛制资料确认：每轮均为七局四胜，采用 `2-2-1-1-1` 主场顺序；首轮固定为 `1v8、4v5、3v6、2v7`，后续按固定对阵树推进。
- 参考资料：
  - https://cdn.nba.com/teams/uploads/sites/1610612760/2023/10/mediaguide-2324.pdf
  - https://www.nba.com/news/2025-nba-playoffs-standings-and-bracket-updates
  - https://www.nba.com/news/playoff-race-breakdown-houston-rockets-and-golden-state-warriors
- 游戏运行时继续只显示中文球队简称和纯代表色；不得增加联盟名称、联盟标志、球队标志或仿制球衣图案。
- 本阶段只闭合首年冠军路径。年龄增长、衰退、强制退役、退役通知和下一赛季属于 M6B-3。

## 2. 固定对阵树

每个赛区的八支球队使用附加赛结束后的最终种子，且整个季后赛不重新排种子：

1. 首轮 F1：1号种子 vs 8号种子
2. 首轮 F2：4号种子 vs 5号种子
3. 首轮 F3：3号种子 vs 6号种子
4. 首轮 F4：2号种子 vs 7号种子
5. 分区半决赛 S1：F1 胜者 vs F2 胜者
6. 分区半决赛 S2：F3 胜者 vs F4 胜者
7. 分区决赛 C1：S1 胜者 vs S2 胜者
8. 总决赛：东部冠军 vs 西部冠军

下一轮系列赛只在两个来源系列赛都已结束后生成一次；不会因为其他对阵仍在进行而重排。东西部和同轮不同系列赛可以交错推进。

## 3. 七局四胜与合法比赛前沿

- 每个系列赛先胜四场者立即赢得系列赛，最少四场、最多七场。
- 主场优势方依次承办第 `1、2、5、7` 场；另一方承办第 `3、4、6` 场，即 `H、H、A、A、H、A、H`。
- 每个未结束系列赛始终只有一个 `SCHEDULED` 比赛前沿；其余场次不得提前生成或结算。
- 只允许结算当前前沿。不得平局、跳场、越轮、在系列赛结束后追加比赛或覆盖既有终场比分。
- 同比分重复提交为 `NOOP`；同一场不同比分为 `CONFLICT`；不匹配当前根 revision 的提交为 `STALE`；所有拒绝均不增加 revision 或事件。
- 达到四胜后立即锁定胜者和败者，不生成多余比赛，并在来源齐备时只生成一个下轮系列赛。

## 4. 主场优势

### 同赛区系列赛

- 比较两队冻结的常规赛战绩；战绩更好的球队拥有主场优势。
- 战绩相同时沿用冻结排名的完整同战绩判定结果，即原始赛区种子更高者拥有主场优势。
- 后轮不因爆冷而重新排种子；但主场优势仍在该轮两支实际晋级球队之间按上述口径决定。

### 总决赛

依次比较：

1. 常规赛胜率；
2. 两队常规赛相互交手胜率；
3. 对另一赛区球队的常规赛胜率；
4. 若仍完全相同，使用 `freezeEventId + 两队有序ID` 的确定性抽签。

该比较只读取已经结束并随根存档保存的常规赛，不读取季后赛战绩，也不依赖东西部推进先后。

## 5. 系列赛事件与确定性模拟

- 系列赛、比赛和事件 ID 由冻结事件、赛区/轮次/固定槽位、参赛球队及场次号组成，不使用点击顺序或全局 revision 生成身份。
- 每场模拟种子至少包含 `season.seed + seriesId + gameNumber`。同一存档、同一场次刷新后得到同一结果；同一系列赛不同场次不会因复用基础 seed 而机械重复比分。
- 模拟和手打都走同一个 `recordPlayoffGameResult` 结算入口；两条路径只能结算一次。
- 根 `revision` 每个已应用比赛只增加一次；系列赛 revision 只计算本系列赛已结束场次。

## 6. 统计、奖励、默契与体能

- M6B-2 只持久化球队级的比赛比分、系列赛胜场、晋级、分区冠军和总冠军。
- 季后赛个人统计必须与常规赛 `PlayerSeasonLine` 分开；本阶段不把手打临时 box score 汇总进常规赛或奖项口径。
- 为保证手打和模拟公平，本阶段所有季后赛比赛均不发金币、不改变默契、不消耗训练次数，也不写入尚未建模的长期体能。
- 未来若增加季后赛个人统计或奖励，必须升级存档版本并为模拟与手打提供同口径数据，而不是回写常规赛字段。

## 7. 存档版本与迁移

- `PostseasonState.schemaVersion` 从 1 升到 2，新增系列赛 bracket。
- 根 `CareerSaveEnvelope.schemaVersion` 从 2 升到 3；localStorage key 仍保持 `wo-neng-da-zhi-ye:career:v1`，稳定命名空间不改名。
- 根 v1（无季后赛）继续迁移；根 v2 + Postseason v1 必须在内存中迁移为 v3 + Postseason v2。
- 迁移不得重算或重抽已冻结排名及已完成附加赛结果。若两区附加赛均完成，则从其最终 1–8 种子确定性生成首轮；否则 series bracket 保持未创建。
- 未来根 v4+ 或 Postseason v3+ 一律拒绝并保持只读；损坏的来源链、胜场、主客顺序、事件账本或冠军链进入 `RECOVERY_REQUIRED`，不得静默覆盖。

## 8. UI 与操作契约

- 季后赛中心增加：附加赛、首轮、分区半决赛、分区决赛、总决赛五个阶段入口。
- 系列赛卡显示双方、总比分、当前/下一场、主客场、晋级或淘汰状态。
- 只有合法前沿显示操作：创建球员所属球队参赛时同时提供“亲自比赛”和“模拟本场”；其他比赛只提供“模拟本场”。
- 所有启用按钮都必须改变真实状态或给出明确拒绝原因；提交过程中锁定重复点击，写盘失败保留结算界面并允许重试。
- 手打继续复用完整比赛引擎，但使用显式 `PLAYOFF_SERIES` 上下文，不能落入常规赛金币/默契结算分支。
- 桌面与 844×390、852×393 iPhone 横屏均要求无溢出，主要按钮触控尺寸至少 44px。

## 9. 完成判定

- 两个赛区冠军均产生前不得存在总决赛。
- 总决赛一方达到四胜时只生成一个总冠军；之后所有季后赛比赛输入锁定。
- 事件重放必须能从冻结状态恢复完全相同的系列赛、冠军和 revision。
- focused domain/save、完整 core、桌面 Playwright、原生 WebKit、生产 build、受保护运行时和内容扫描全部退出码为 0 后，M6B-2 才能标记为 DONE。
