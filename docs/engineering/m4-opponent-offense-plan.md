# M4 对手进攻：实施计划

版本：1.0（2026-09-01）
状态：已实施并通过本轮纵向切片验收；作为 M4B 的实现与回归基线
范围：让对手在同一回合状态机内完成落位、发起、阅读防守、第二选择、失败回落和终结，并以固定种子可复现。

## 1. 目标与边界

本轮把现有“对手按位置移动、四套预设路线”升级为可解释的进攻执行器。NCAA 与教练教育材料只用于提炼篮球通用原理；比赛仍遵守项目已冻结的 24 秒、14 秒和 M3A 回合流程，不引入 NCAA 的另一套计时规则。

必须完成：

- 对手根据阵容、实际防守、比分、剩余时间、体能和近期调用记录选择战术。
- 每套战术都有初始落位、触发、第一阅读、第二阅读、失败回落与防守破解分支。
- 战术先移动并形成真实空间，再由统一结算公式决定传球、投篮、突破或失误；战术不是必得分按钮。
- 玩家能够从棋子路线、持球点和简短事件说明看出对手意图，并在关键节点用现有防守动作回应。
- 同种子、同状态、同输入序列产生相同战术、路线、对位和结果日志。

本轮不包含犯规/罚球、换人、球队暂停、完整边线球库、教练挑战或真实球队专属内容；这些不能用占位判断冒充完成。

## 2. 统一战术数据契约

战术是纯数据图，执行器只识别语义区域和动作节点，不把某张战术图的绝对坐标写进规则。

```text
OpponentPlay {
  id
  family
  eligiblePhases
  requiredRoles
  alignment[]       // slot、wing、corner、elbow、block、dunker、trail 等语义区域
  trigger
  primaryReads[]
  secondaryReads[]
  fallback
  counters[]
  clockBudget
  cooldownTags[]
}

Read {
  condition          // deny、trail、topLock、switch、drop、hedge、blitz、zone、lateClock...
  intent
  routeDependencies  // 谁先到掩护点、谁接球后才能启动下一节点
  outcomeCandidates
}
```

角色使用 `handler`、`shooter`、`connector`、`screener`、`roller`、`postHub`、`rimRunner`，再由当前五人属性匹配。球员号码和名义位置不直接锁死角色；无法满足必要角色时降低战术适配分，不强行执行失真的路线。

## 4. 选战术与读防

对手每个球权最多在落位前选一次主战术，失败回落只沿战术图迁移，不重新全局抽签。选择效用建议为：

```text
utility = familyBase
        + lineupFit
        + matchupFit
        + defenseResponseFit
        + scoreClockFit
        + spacingQuality
        - fatigueCost
        - recentUsePenalty
        + seededDecisionNoise
```

- `lineupFit` 读取五名在场球员实际属性，而不是总评。
- `matchupFit` 只读取当前唯一对位；换防后必须使用新防守者。
- `defenseResponseFit` 来自实际人盯人、换防、沉退、夹击或联防状态，不偷看玩家未来输入。
- `recentUsePenalty` 对同 family 和相同终结点设置冷却，避免连续机械复读；冷却只改变权重，不永久禁用合理战术。
- 随机只使用比赛种子提供的决策流。运动插值、展示帧和路线绘制不得消耗规则随机数。

每个阅读节点只从当前可见状态作决定。高篮球智商、传球视野和决策速度提高选中高效目标的概率并缩短犹豫，但低属性仍可偶尔做出正确选择，高属性也不能达到 100%。

## 5. 唯一计时器与状态机边界

M3A 的 `advance(elapsedMs)` 继续是比赛钟、进攻钟、5秒、8秒和快攻窗口的唯一写入口。对手战术执行器：

- 只读取 `phase`、`possessionId`、`decisionEpoch`、剩余时钟和累计模拟时间；不读取 `Date.now()`，不创建 `setTimeout`/`setInterval`，也不直接扣秒。
- 用 `aiDecisionClock`、`decisionToken` 和路线完成条件表达延迟；每次主循环推进后，控制器最多提交一个语义节点。
- 战术子状态仅存在于允许对手持球的 `FASTBREAK`、`SET_OFFENSE` 或 `SECOND_DECISION` 内：

```text
ALIGN -> TRIGGER -> PRIMARY_READ -> SECONDARY_READ -> FALLBACK -> RESOLVE
```

- `PRIMARY_READ` 可直接进入 `RESOLVE`；只有没有合格机会时才进入第二阅读或回落，不能为凑齐动画强行走完所有节点。
- 死球、球权变化、出界、节末、终场、暂停和后台冻结会原子取消旧 `playToken`、路线、速度、响应窗口和待结算意图。
- 每个节点携带 `possessionId + playToken + nodeId`；旧令牌回调为 no-op，重复提交不得重复传球、投篮、得分或翻转球权。
- 快攻 6 秒窗口到期只令 `EARLY_DHO` 回落到阵地，不重置两个主时钟、比分、持球人或随机序列。
- 剩余 7 秒以下禁止启动需要多个依赖节点的完整战术，只能选择已经形成的机会或统一 late-clock 双人动作。

## 6. 属性、命中率与难度原则

战术选择、动作执行和最终命中分三层结算，任何属性或难度倍率不得重复进入多层。

1. **选择层**：`basketballIQ`、`passVision`、`decisionSpeed`、`offBallMovement` 与阵容默契决定是否识别第一/第二机会；不直接决定投篮命中。
2. **执行层**：传球读取准确、速度、护球、接球者双手和真实抢断线路；掩护读取力量、篮球智商、站位、接触是否成立；移动读取速度、加速度、体能和路线长度。
3. **结果层**：投篮读取对应区域能力、接投/急停情境、稳定性、体能、真实空间、当前对位和实际到位的协防；终结读取近筐/上篮/扣篮、力量、弹跳，对比能沿路线及时到达的内防与盖帽。

结果概率采用版本化权重、归一化属性和逻辑函数：

```text
z = offenseContribution
  - onBallDefenseContribution
  - arrivedHelpContribution
  + spacingModifier
  + timingModifier
  + shotContextModifier

p = clamp(sigmoid(z), lowerBound, upperBound)
```

- 普通事件保留 5%–95% 区间；传球完成率可使用 40%–99%。不为任何战术设置固定命中率或必进分支。
- 只有沿真实路径及时到位的协防者进入 `arrivedHelpContribution`；协防离开弱侧后同步提高对应接应点的开放度。
- 有效能力保持 `clamp(base + chemistryBonus + temporaryModifier, 25, 99)`，不改写存档原始值。
- 已冻结难度系数只缩放**玩家控制球员**在概率中的正向贡献一次：新秀 1.20、职业 0.90、首发球员 0.80、全明星 0.75、名人堂 0.70。对手进攻时，如果玩家是本次实际防守者，该系数只作用于玩家的防守贡献；不得再提高对手投篮属性或在终结阶段二次乘算。
- 其余对手与队友保持真实有效属性。若以后需要不同 AI 阅读水平，应另设可测试的 `aiDecisionProfile`，不能借“难度”暗中改随机数、移动速度或原始属性。
- 必须满足单调性：提高相关进攻属性不降低成功率；提高实际到位的防守属性不提高对手命中率；更好空间和更低干扰不降低同类出手机会质量。

## 7. 事件解释与界面接入

- 事件日志只显示一行原因链，例如“高位下切被换防 → 内线封住小个 → 弱侧协防到位，回传外线”，不展示内部权重或骰子。
- 路线层继续读取每名球员真实 `motion.routes`；战术预告线与已承诺路线应有不同样式，但不能新增装饰性硬编码路径。
- 玩家控制权始终只属于已创建球员。检查其他棋子不转移控制；防守回应仍通过右侧固定五槽表达。
- 对手属性不在暂停数据页泄露；只公开比赛中可观察的意图、对位与结果原因。
