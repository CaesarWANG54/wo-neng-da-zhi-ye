# 《我能打职业》原型制作与工程实施计划

版本：0.9（2026-09-09 私有公测代码候选）
目标平台：手机横屏
当前范围：先完成可验证的比赛纵向切片，再逐步扩展为完整生涯循环。

## 1. 执行原则

- 每次只推进一个可独立验收的小任务；未达到退出条件，不进入下一任务。
- 比赛结果必须由规则层产生，界面只负责展示与输入，避免动画或按钮直接改比分。
- 所有概率均从同一个可注入的固定种子随机源获取；禁止在核心规则中直接调用非确定性随机数。
- 先使用原创、合成或已核准的数据和视觉资产。球队只显示获准的中文简称与纯色，不显示联盟字样、联盟标志、球队标志或仿制球衣图案。
- 每个里程碑都保留测试报告、截图或构建日志作为验收证据，并记录尚未覆盖的风险。

状态说明：`已完成` 表示当前范围已实现并有自动证据；`候选完成` 表示功能与聚焦证据已落地，但本轮完整放行链仍有至少一项未全绿；`部分完成` 表示已有可运行纵向切片，但仍有明确缺口；`规范完成` 表示规则已冻结但没有运行时代码；`受阻` 表示还受数据、许可或产品决策门禁限制；`计划` 表示尚未开始。逐项真相以 [项目落实状态矩阵](project-status-matrix.md) 为准。

## 3. M0 — 需求、边界与技术预研（已完成）

小任务：M0.1 固化核心体验；M0.2 对照同类战术篮球产品；M0.3 建立品牌与数据使用边界；M0.4 确定验收方式。

- 输入：产品构想、选定的纸张战术板参考图、右手操作要求、比赛及生涯规则清单。
- 实现：把体验拆成比赛规则层、输入仲裁层、展示层和长期生涯层；确定 React + TypeScript + Vite 作为原型技术栈，后续用移动端容器封装；建立“不展示禁用字样和标志”的运行时边界。
- 自检：逐条核对核心操作、挡拆逻辑、比分牌、帮助、暂停、球员圆点与球衣号码是否均有归属模块；确认同类产品仅用于学习流程与信息架构，不复制其界面、文案、图标或数值表。
- 验收：需求清单可以映射到 M1–M9；任何未落入里程碑的需求必须登记为待决项。
- 退出条件：视觉方向、首个可玩场景、技术栈和合规边界均已明确，才可搭建工程。

## 4. M1 — 工程底座与战术板骨架（已完成）

小任务：M1.1 初始化移动端工程；M1.2 建立横屏安全区；M1.3 接入原创纸张球场；M1.4 建立比赛界面组件边界。

- 输入：M0 产物、目标横屏尺寸、原创纸张球场资产和所选界面参考。
- 实现：建立应用入口、比赛页、样式文件、球场、比分牌、24 秒计时、右侧五键操作栏、圆形棋子、号码、帮助与暂停弹层；保留设备外壳的受保护运行时。
- 自检：运行类型检查和生产构建；检查战术板是最大视觉区域，右手拇指可触达五键，按钮与设备摄像头安全区不重叠。
- 验收：应用可在本地启动；比赛页无横向滚动、文字截断或按钮互相覆盖；基础构建通过。
- 退出条件：静态界面在主目标机型上可完整显示，组件边界允许规则层独立测试。

## 5. M2 — 核心比赛纵向切片（已完成）

小任务：M2.1 固定种子与合成球员；M2.2 进攻、有球、无球和防守上下文；M2.3 挡拆状态机；M2.4 双击仲裁；M2.5 得分、失误、篮板、快攻、发球与推进；M2.6 单元测试和界面冒烟测试。

- 输入：10 名合成球员的能力值、60:60/第 4 节/03:00/24 秒的教学场景、五个右手按钮和挡拆规则。
- 实现：
  - 统一固定种子随机源，保证同一输入可复现同一结果。
  - 有球时支持传球、突破、投篮、挡拆、战术；无球时支持要球、空切、外弹站位、给持球队友挡拆、战术；防守时切换为跟防、抢断、干扰、换防、联防。
  - 持球挡拆与无球掩护采用不同发起者语义；防守可换防、沉退、夹击、延误或绕掩护；掩护人可顺下、外弹、短顺下或假掩护。
  - 换防结果原子更新对位；后续投篮读取当前实际外线防守人。十人坐标、动作路线和攻防意图已进入比赛状态；突破按实时坐标读取走廊阻挡和篮筐4.35米内护筐者。一次点击后空篮先移动到距筐约2.25米内再自动扣篮；阵地受保护时也在近筐自动进入以上篮为主的终结判定；突破途中单击传球立即优先打断终结并突分给最近合法外线队友。
  - 260 毫秒窗口仲裁单击与双击；双击传球仅尝试空接，双击投篮仅尝试扣篮，路线不成立时给出明确失败原因，不静默降级为普通动作。
  - 处理命中、打铁、篮板、失误、14 秒重置、转换快攻、底线或边线发球和运球推进。
- 自检：运行核心测试；使用浏览器自动化点击挡拆、帮助、暂停和五个按钮；检查控制台错误、按钮数量、几何尺寸、提示文案与路线路径。
- 验收：固定种子、双击分类、换防原子性、当前防守人减益和候选协防属性单调性通过自动测试；iPhone 主目标画面五键无重叠；生产构建通过。
- 退出条件：玩家能在一个回合中观察输入、规则判定、棋子移动、提示和比分变化的完整因果链；具体证据以验收矩阵为准。

## 6. M3A — 完整回合流转（已完成）

小任务：M3A.1 真实比赛时钟与 24/14 秒；M3A.2 出界、死球与底线/边线发球；M3A.3 发球 5 秒和后场 8 秒；M3A.4 快攻 6 秒窗口与转阵地；M3A.5 节间、加时和比赛结束；M3A.6 暂停、玩法页与后台冻结；M3A.7 移动端阶段反馈与自动验收。

- 输入：M2 单回合控制器、每节 2/3/6 分钟设置、职业篮球通行的计时与发球边界。
- 实现：动作结算与时间推进彻底解耦；唯一 `advanceMatchTime(elapsedMs)` 以不大于50ms的子步处理真实时间和同时到期优先级；显式实现 `DEAD_BALL → INBOUND_READY → BACKCOURT_ADVANCE → SET_OFFENSE`、`FASTBREAK → SET_OFFENSE`、普通节间底线发球、加时跳球与 `FINAL`。后场阶段必须由持球点实际越过中线结束，不再按固定1.2秒假定完成。传球、空接、手递手和发球把百分比坐标按28.65m×15.24m换算为米制距离并建立唯一飞行状态；所有自动迁移使用阶段令牌且终场幂等。
- 自检：核心测试覆盖 24/8/5 秒、24/14 秒重置、最后触球出界表、换防回位、快攻降速、普通节间发球、连续加时、统计与状态不变量，以及 500 次强制球权转换浸泡；浏览器测试覆盖实时时钟、暂停/后台恢复、发球链、快攻持球/无球输入、双击、加时、终场和双机几何。测试数量以自动命令输出为准，不在计划中硬编码。
- 验收：动作不会固定扣时或双重扣时；进球只得分一次、球权只翻转一次；出界按最后触球方保留或转换球权；普通防守碰出且进攻保留时沿用未使用进攻时间，只有触圈保有球权等明确规则原因才回到 14 秒；快攻到期不重置主时钟；第四节同分进入加时、非同分只结算一次；`FINAL` 对计时和比赛动作严格 no-op。
- 证据：`src/game/flow.test.ts`、`tests/game-flow.spec.ts`、`docs/engineering/m3a-possession-flow-plan.md` 与验收矩阵 M3A 条目。
- 退出条件：本轮用户指定的真实计时、出界发球、死球、快攻转阵地和比赛结束全部可运行、可见、可复现且可自动验收。

## 6.1 M3B — 裁判闭环（已完成当前场上十人纵向切片）

小任务：M3B.1 犯规与球队处罚；M3B.2 独立 `FREE_THROW` 状态、自动罚球与合法站位；M3B.3 进攻/防守三秒；M3B.4 防守干扰球与进攻干扰；M3B.5 六犯登记；M3B.6 十人逐球员技术统计与暂停表；M3B.7 聚焦规则/UI验收；M3B.8 自然犯规频率门与创建球员常驻约束。

- 输入：M3A 权威计时与发球链、38项合成能力、十人位置和官方规则第3/9/10/11/12条。
- 实现：投篮犯规支持加罚、两罚和三罚；普通犯规按常规/加时球队犯规与最后两分钟额度决定前场续权或两罚；进攻撞人/非法掩护记犯规和失误但不进入球队处罚。自然接触的基础概率已下调，玩家与电脑的自然个人犯规共用全局滑动门：任意10个新进攻回合最多1次；自然三分投篮犯规另受任意50回合最多1次约束，两种情况都允许窗口内为0。新回合只在一队新获球权时登记，进攻篮板、防守碰出续权和普通犯规续权不重复计数；强制规则事件与QA注入绕过自然频率门。罚球无需按键，实际罚球队员移到罚球线，普通罚球由3名防守与2名进攻球员占篮下分位，其余4人退到外线；防守三秒技术罚球不占分位且原进攻方续权。最后一罚触圈未中进入原十人篮板。进攻三秒记实际球员失误并换权；防守三秒执行1次技术罚球；防守干扰球判给原出手分值，进攻干扰取消得分并记实际触球队员失误。主客各5人的个人账本按ID记录投篮、三分、罚球、篮板、助攻、抢断、盖帽、失误、犯规、时间和正负值，暂停页显示双方五人比赛数据。创建球员固定保留在场上五人中，不参加常规轮换。
- 自检：纯规则测试验证处罚阈值、属性单调性、固定种子、10/50回合双层滑动上限、续权不误增回合和双方共用窗口；状态测试验证罚球冻表/落位/逐罚/最后一罚、三秒、干扰球、六犯、创建球员常驻与比分统计守恒；界面测试验证罚球横幅、站位角色、创建球员红圈不随罚球人迁移、五键锁定和双方五人统计表。
- 验收：最新 `npm run verify` 与 `npm run test:sites` 退出码均为0；核心规则17个文件216项、移动端Playwright 72项、发布包4项全部通过，类型检查、运行时完整性、生产构建与内容合规扫描也全部通过。证据与边界见 [M3B实施说明](m3b-officiating-plan.md) 和 [M3B验收报告](../acceptance/m3b-acceptance-report.md)。
- 未包含：替补席及非创建球员的完整轮换、球队暂停次数、教练挑战、争球、全部罚球违例和玩家主动触碰空中篮球；八秒与回场已作为独立违例接入。当前没有轮换引擎，创建球员保持登场，第六犯只登记犯满而不触发换人。

## 6.2 M3C — 合成 38 项属性基础层（已完成）

- 已把运行时 `Ratings` 从 22 项迁移为恰好 38 个稳定字段，并用 `RATING_SCHEMA_VERSION`、字段列表及整数 `25..99` 校验器阻止缺项、越界和额外字段。
- 10 名原型球员仍为原创合成数据，不是任何真人或竞品数据表；投篮、终结、传球、挡拆、无球跑位和篮板公式已读取相应新增字段。
- 当前38/38项均已进入至少一个比赛、裁判、电脑决策、运动或传球公式；M3B 已让 `drawFoul` 进入下调后的自然接触犯规概率、`freeThrow` 进入自动罚球概率，`standingDunk` 也已参与现有近筐终结。属性可以在低基础概率内改善造犯规机会，但不能绕过10/50回合的全局频率上限。`standingDunk` 仍没有单独站扣操作入口，不能据此宣称全部38项都有独立动作。
- schema v4 根存档已经实现并正式通过，包含 v1/v2/v3 内存迁移、损坏档恢复、季后赛个人统计、季末状态和紧凑历史交叉校验；真人数据模板生成器与字段级来源链仍是后续任务，详见 [当前数据清单](../data/current-data-inventory.md)。

## 7. M4 — 战术、对位与电脑决策（当前纵向切片已完成）

小任务：M4.1 五外、Horns、手递手、梯次掩护；M4.2 挡拆防守策略；M4.3 无球跑位和空间评分；M4.4 联防与破解；M4.5 电脑选择解释器；M4.6 难度参数化。

- 输入：M3 稳定回合状态机、合成 38 项属性基础层、战术站位点和路径数据。
- 当前落地：确定性运动内核不消耗比赛随机种子或决策序号；AI队友和对手按角色锚点、当前对位、护筐职责与比赛阶段移动。玩家四套战术均生成上下侧、三种语义分支、主参与者、四阶段进度和执行质量；最近签名防止相邻重复，当前节点/角色/反制可见，且执行质量以封顶3个百分点进入传球、投篮和突破。电脑半场进攻从九类通用战术族选择，相邻回合硬排除上一战术，并继续使用侧向和几何签名去重；命中并非必然，五个防守键都有持续反馈并实际影响路线、对位或概率。
- 当前落地补充：普通传球已评估持球人之外全部四名合法队友，以实时空间、得分区域、战术角色、距离与防守线路风险评分；篮球智商、视野、决策和准确决定最优/次优选择，准确、护球、速度与线路风险决定送达。防守碰出与直接截断分流，固定释放落点和到达交接语义不变。
- 当前缺口：更细的接触/争抢犯规触发、指定接球队友/传球假动作、更多联防和完整界外球战术仍需扩展。逐球员统计基础账本与暂停表已由 M3B 落地，但替补阵容和赛季累计尚未实现。
