# M6B-3 季后赛个人统计与跨赛季循环验收报告

日期：2026-09-03
状态：**已完成（DONE）**
放行结论：**M6B-3正式放行；2026-09-03 D盘正式树五项门禁全部通过。**

## 1. 本阶段范围

M6B-3 在既有 M6B-2 唯一冠军闭环之后增加：

- 创建球员附加赛与正式季后赛的独立个人统计；
- 根生涯存档 schema v4 与 v1/v2/v3 内存迁移；
- 常规赛、奖项、冠军、完成事件和个人统计的一致性结算门禁；
- 季末年龄增长、32岁后确定性衰退和成长账本；
- 合成退役通知、受许可真人内容钩子和通知确认；
- 40岁强制退役、无第21个可比赛赛季；
- 第2至第20季的项目生成赛程、紧凑历史与下一赛季循环；
- 固定种子20赛季SOAK。

本阶段不新增季后赛金币或默契奖励，不把季后赛数据写入常规赛统计/奖项，不实现合同、交易、伤病、季后赛疲劳、最近五场实战校准或真人阵容。

## 2. 已实现事实

### 2.1 季后赛个人统计

- `CareerPostseasonPerformanceState` 将数据分为 `PLAY_IN` 与 `PLAYOFF` 两个桶。
- 每个桶保存不可变逐场记录，以及只能由逐场记录重放得到的13项合计。
- 手打数据来自比赛十人账本；模拟数据使用相同结构与合法性检查。
- 每条记录绑定 `gameId`、比分事件、阶段、来源、球队、对手、主客场、比分和球员行。
- 相同记录重放为 `NOOP`；相同比赛/事件的不同内容拒绝。
- 全新生涯要求玩家球队每场已结束季后赛都被统计；旧档无法恢复的行登记为 `PARTIAL_LEGACY`、追踪起始revision和明确比赛ID，不从球队比分虚构个人数据。

### 2.2 季末状态机

季末结算必须同时满足：

1. 1,230场常规赛全部结束并完成动态杯赛；
2. 当前赛季拥有精确奖项集合；
3. 季后赛冻结树可由当前常规赛重放；
4. 东西部冠军、唯一总冠军和唯一赛季完成事件均存在；
5. 玩家球队所有已结束季后赛个人统计已完整记录或被旧档覆盖标记解释；
6. 活动赛季、年龄、成长账本、历史摘要和已处理事件一致。

通过后依次生成不可变赛季摘要、年龄变化与衰退账本、持久化通知，再等待玩家开始下一季或确认退役。相同完成事件重放为 `NOOP`；不同事件、跨季冻结树、统计球队错误、历史缺口或分裂账本均拒绝。

### 2.3 年龄、衰退和退役

- 创建球员20岁进入第1季；年龄与可比赛赛季满足`age = seasonNumber + 19`。
- 20–31岁无固定年龄衰退；`31→32`首次执行1点运动能力预算。
- 后续预算按冻结表确定性分配，每个下降点单独写入`AGE`账本，永久能力保持`25..99`。
- 本阶段不启用隐藏经验保护、随机技术不降或低概率技术`+1`。
- `39→40`只结算一次；球员退役但最终可比赛赛季仍为第20季，不创建第21季。
- 退役后比赛、训练、购买、奖励和默契变更入口必须冻结。

### 2.4 下一赛季和未来赛程

- 第1季保留审定的2026–27赛程快照。
- 第2–20季使用确定性项目生成赛程，领域来源为`PROJECTED`，界面显示“项目生成赛程”；不得宣称为现实发布或实时同步赛程。
- 每季创建1,200场基础对阵，再解析30场动态杯赛，保证30队各82场。
- 新季保留永久能力、金币、默契、副属性进度、成长账本和历史事件；重置当季赛果、战绩、统计、奖项、季后赛、训练周和训练荒瞬态。
- 第2季起不再生成最佳新秀和最佳新秀阵容。
- 完成季只归档紧凑摘要，不复制整份1,230场旧赛程。

### 2.5 内容与权利门禁

- 联盟退役通知默认使用项目原创合成英文姓名，不代表现实退役名单。
- 真人姓名、音译、称号或指定退役剧情只能从独立 `ApprovedRetirementContentEvent` 钩子进入。
- 只有 `rightsStatus === "APPROVED"` 且赛季、球队、年龄、姓名、原因和唯一ID均合法的内容可显示；`REVIEW`、`BLOCKED`、空字段、非法年龄、未知球队和重复ID被过滤。
- 当前已批准真人退役内容数量为0；不得把任何特定真人退役写成已实现事实。
