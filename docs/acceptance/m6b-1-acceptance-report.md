# M6B-1 最终排名冻结与附加赛验收

日期：2026-09-03
正式项目：`D:\我能打职业`
结论：M6B-1 当前承诺范围通过；M6 总里程碑仍为 PARTIAL。

## 1. 本轮交付

- 只有杯赛已解析、联盟恰有 1,230 场且 30 队各 82 场全部终场时，才允许冻结常规赛。
- 东西部各保存 15 队最终排名快照；界面展示前十，1–6 直通、7–10 进入附加赛。
- 两队与多队同战绩规则分开执行，并覆盖分区冠军、相互战绩、分区/分区内战绩、符合资格对手战绩、净胜分及稳定随机抽签兜底。
- 每区附加赛严格按 A（7主8）、B（9主10）、C（A负者主B胜者）推进；C 只在 A、B 都结束后生成。
- 玩家可按产品要求选择亲自比赛或模拟本队下一场；其他场次可模拟。模拟结果只取固定场次身份与赛季种子，不受先推进东部还是西部影响。
- 手打复用完整比赛引擎，并把“玩家比分/对手比分”映射回真实主客队；附加赛当前只写比分、胜负、晋级和稳定事件，不重复计入常规赛战绩、82场个人统计、金币或默契。
- 根存档升级到 schema v2，v1 在内存安全迁移；季后赛切片会与最终常规赛和事件重放结果交叉校验。坏档进入恢复流程，不静默重抽排名。
- 日历新增“季后赛中心”，支持东西部切换、前十排名、A/B/C 对阵、模拟、手打确认、终场结算、错误重试和刷新恢复。

## 2. 原子性与防重验收

- 冻结重复调用返回原状态，不增加季后赛或根存档 revision。
- 附加赛相同终场比分为 NOOP；不同比分重放、平局、越序场次、错误对阵和陈旧 revision 均拒绝。
- 东西部交错推进的事件 ID 与重放顺序无关；两区都有结果后仍可保存和恢复。
- 写盘失败时终场对话框保持打开，内存 UI 与根存档都不提交；恢复存储后可重试。
- 对结算按钮连续触发两次，只新增一个季后赛事件和一个季后赛 revision。
