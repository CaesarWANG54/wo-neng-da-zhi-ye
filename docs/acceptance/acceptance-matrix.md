## 3. 验收执行顺序

1. 先执行 `CORE`、`INPUT`、`PNR`、`DEF` 单元测试；任何失败立即停止，不进入界面验收。
2. 再执行 `FLOW` 状态机测试，确认比分、时钟和球权守恒。
3. 启动生产构建预览，执行 `UI` 的自动化几何检查和 iPhone/Pixel 截图比对。
4. 执行 `SAFE` 文字与资产扫描；扫描结果必须人工复核，不能只依赖文件名。
5. 最后执行 `BUILD` 干净构建，并保存命令、退出码、日期、提交版本和产物哈希。

## 4. 缺陷等级与放行规则

- P0：崩溃、存档损坏、无法继续比赛、重复扣款或严重权利风险。发现即停止。
- P1：比分/球权/计时错误，挡拆对位错误，双击触发两次动作，按钮被安全区遮挡。发布前必须清零。
- P2：低频动画错位、非关键文案或轻微布局问题。必须登记负责人和目标版本。
- P3：视觉润色或不影响理解的反馈问题。可进入后续迭代，但需保留复现步骤。

当前 M2、M3A、M3B、M3C、M4 与 M5 纵向范围只有在所有 `P0/P1` 为零，且对应的“部分通过”缺口已经明确归入后续里程碑时，才可宣布阶段验收结束。M3B只完成当前场上十人的裁判闭环；八秒推进、前场建立后的回场、第5次连续抢断犯规及末节AI战术犯规已加入，但替补换人、球队暂停次数、教练挑战、争球、完整罚球违例或主动空中触球仍未完成。整体项目完成度必须查看 [项目落实状态矩阵](../engineering/project-status-matrix.md)，不能把纵向切片通过等同于完整游戏完成。
