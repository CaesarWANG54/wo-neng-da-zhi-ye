# M6B-2 七场系列赛与首年冠军闭环验收报告

日期：2026-09-03
正式项目：`D:\我能打职业`
结论：**通过（M6B-2 DONE）**

## 1. 本轮目标与边界

本轮在 M6B-1 已冻结的常规赛排名与附加赛之上，完成固定对阵的七场四胜季后赛、分区冠军、总决赛与唯一总冠军，并把手打、模拟、存档迁移和 iPhone 横屏界面接成可落地闭环。

本轮明确不做：季后赛个人累计统计、季后赛金币/默契奖励、长期体能、年龄增长、退役通知和下一赛季。这些内容继续归入 M6B-3 或后续里程碑。

## 2. 已实现范围

- 两区最终八强完成后固定生成 `1v8、4v5、3v6、2v7`；后续严格沿来源支路晋级，不重新排种子。
- 所有系列赛采用七场四胜与 `H-H-A-A-H-A-H`；每个活跃系列赛同刻只有一场合法下一场，四胜后立即锁定且不生成多余比赛。
- 同轮不同系列赛与东西部可交错推进；两个来源齐备后只生成一次下轮；最终恰有15个系列赛、两个分区冠军和一个总冠军。
- 总决赛主场优势按冻结常规赛胜率、相互战绩、跨区战绩、确定性抽签依次判定，不读取点击顺序。
- 季后赛中心可切换附加赛、首轮、分区半决赛、分区决赛和总决赛；卡片显示双方、系列赛比分、下一场、主场、晋级或等待状态。
- 创建球员所在比赛可“亲自比赛”或“模拟本场”；其他合法比赛可模拟。玩家淘汰后仍可继续模拟剩余联盟对局。
- 手打复用完整比赛引擎，并使用独立 `PLAYOFF_SERIES` 上下文；成功结算后自动返回季后赛中心，不进入常规赛奖励分支。
- 根存档升级至 schema v3，支持 root v1/v2 和 Postseason v1 的内存迁移；未来版本拒绝且不覆盖，损坏或篡改状态进入恢复路径。
- 季后赛终场事件绑定准确比分；即使只改一分且不改变胜负，严格重放也会拒绝该存档。

## 3. 实施中发现并关闭的缺陷

1. **最终7/8种子误判无效**：原验证错误要求附加赛后的1–8种子仍按常规赛战绩递减。修正为1–6保持排序，7和8均不得优于6号种子，但7与8之间允许由附加赛结果形成战绩倒序。
2. **比分篡改未被事件识别**：系列赛终场事件ID原先不含比分。现绑定 `homeScore-awayScore`，并补同胜负、不同分差的篡改回归。
3. **根版本与子版本混用**：UI传入整个季后赛revision，领域层却按bracket revision校验，导致按钮可点但不落盘。现先校验root revision，再安全映射到bracket revision。
4. **季后赛开赛产生空存档revision**：附加赛/系列赛的临时比赛启动不再写入无变化的根存档；只有终场结果成功持久化后才提交revision。
5. **结算返回语义不一致**：手打季后赛成功后会自动重开季后赛中心，并聚焦当前已生成的最深轮次。
