# 权利与数据来源台账

## 1. 使用方式

本台账是产品、数据、美术、音频和构建流程的工程门禁，不替代法律审核。任何名称、数值、颜色、素材或外部数据在进入可发布分支前，都必须有一条可追溯记录。用户所称已取得联盟授权，只能作为待核验的许可依据；在收到并核对书面范围前，不推定其覆盖竞品产品、竞品数据库、球员个人权利、球队资产、第三方字体、音乐或其他素材。

最终可用性以权利方书面许可、适用平台与地区要求以及专业审核结论为准。本文件避免对具体内容作未经验证的法律定性。

## 2. 状态与构建规则

| 状态 | 含义 | 构建动作 |
| --- | --- | --- |
| `BLOCKED` | 无可靠来源、无许可文件或范围明显未核对 | 不得进入测试分发与发行包 |
| `REVIEW` | 已有材料，但权利人、范围、期限或再分发条件待确认 | 仅允许隔离开发数据，不得打包 |
| `APPROVED_DEV` | 仅批准内部原型或测试 | 可进入内部构建，发行构建必须排除 |
| `APPROVED_RELEASE` | 已核对书面许可并完成内部批准 | 可按许可范围打包 |
| `REPLACE` | 决定使用原创、合成或已购替代项 | 替换完成并复核后方可关闭 |
| `EXPIRED` | 许可到期、地区或平台不再适用 | 自动阻止新构建并触发下架评估 |

默认状态为 `BLOCKED`。没有记录、记录缺字段或许可文件无法访问，均按 `BLOCKED` 处理。

## 3. 台账字段模板

每个可识别项目单独一行；不得用“全部已授权”覆盖不同权利类型。

| 字段 | 填写要求 |
| --- | --- |
| `asset_id` | 稳定唯一编号，例如 `TEAM_NAME_001` |
| `category` | 名称、颜色、人物、昵称、属性、统计、Logo、球衣、字体、音频等 |
| `item` | 实际进入产品的内容或数据集名称 |
| `intended_use` | 出现页面、玩法用途、是否营销使用 |
| `source` | 原始来源、URL/API/文件名、取得日期和版本 |
| `source_owner` | 数据、素材或标识的提供方/权利方待核身份 |
| `license_document` | 合同、授权函、订单或许可条款的内部索引，不在客户端保存 |
| `licensed_rights` | 获准使用、修改、缓存、展示、再分发和营销的明确范围 |
| `platforms` | iOS、Android、网页、商店素材、广告等 |
| `territories` | 适用国家或地区 |
| `term` | 生效日、到期日、续期与终止条件 |
| `attribution` | 是否必须署名及具体展示要求 |
| `restrictions` | 不得修改、不得营销、调用限额、不可离线分发等 |
| `transform_notes` | 翻译、音译、归一化、推演或替换方式 |
| `data_lineage` | 原始输入、处理脚本、人工调整人与输出版本 |
| `status` | 使用上表中的状态 |
| `owner` | 内部责任人 |
| `reviewer` | 产品、数据、品牌/权利审核人 |
| `last_reviewed` | 最近复核日期 |
| `build_gate` | 对应的自动扫描、白名单或排除规则 |
| `evidence_path` | 许可与审核证据的受限内部路径 |
| `notes` | 未决问题、替代方案和下次复核时间 |

## 4. 分类台账与最低核验项

| 分类 | 需要单独登记的对象 | 最低核验项 | 无批准时的工程替代 |
| --- | --- | --- | --- |
| 联盟名称与标识 | 联盟全称、简称、字样、Logo、奖杯与赛事标识 | 文字与图形是否分别覆盖；游戏内、商店页和营销是否覆盖 | 使用原创联盟设定和中性术语 |
| 球队中文短名 | 每支球队的中文短名 | 许可是否覆盖本地化名称、游戏展示和营销；允许的写法 | 使用原创队名或编号 |
| 球队代表色 | 每队的单色值及组合规则 | 颜色值、组合、使用场景与视觉识别限制是否在许可范围 | 使用原创调色板并避免可识别组合 |
| 真人中文音译 | 每名真实球员的中文显示名 | 书面范围是否覆盖人物识别、本地化、平台、地区和期限 | 使用不对应真人的合成球员 |
| 真人昵称/称号 | 每个“字母哥”等昵称或称号 | 昵称本身、人物识别和商业展示是否获准；避免贬义或争议性称呼 | 仅用已批准音译名或合成名 |
| 38 项球员属性 | 每名球员、每版本、每项属性及生成来源 | 字段定义、数据来源、推演方法、审核依据与版本；是否含第三方数据 | 使用原创模型与合成数据 |
| 官方统计 | 比赛日志、赛季统计、高阶统计、名单与赛程 | API/网站条款、缓存、抓取、修改、离线再分发、署名和更新频率 | 使用获准数据源或内部手工小样本 |
| 竞品数值 | 竞品球员总评、逐项属性、隐藏阈值或数据库 | 必须核验竞品权利方的单独书面许可及其再分发/改编范围 | 不导入；依据获准统计与原创规则推演 |
| 球队 Logo | 主标、复古标、局部图形和衍生图案 | 具体版本、尺寸、颜色、平台和营销范围 | 仅显示纯文字和原创几何标记 |
| 球衣与装备 | 版型、条纹、号码字体、赞助标、鞋服与配色组合 | 每个图形、品牌、赞助方和球衣版本的许可 | 使用原创单色小球衣与通用号码 |
| 字体 | 界面字体、号码字体、标题字体及字重文件 | App 嵌入、商用、子集化、修改、跨平台和营销许可 | 使用明确允许嵌入的开源/自购字体 |
| 图标与插画 | 操作图标、奖项、战术图和装饰图 | 来源、许可证、署名、修改与分发条件 | 使用项目原创或已批准图标库 |
| 音效与音乐 | 点击、哨声、球场声、观众、配乐与配音 | 录音和作品权利、循环/剪辑、平台、地区、期限及营销 | 使用原创录制或明确商用授权素材 |
| 教练与其他真人 | 教练、裁判、解说或管理人员姓名、昵称与形象 | 人物识别与具体使用范围 | 合成人物 |
| 生成球员姓名 | 随机英文姓名组合 | 与真实知名球员、商标或不当词汇的碰撞检查 | 重新生成并维护禁用词表 |

### 4.1 竞品精确数值专项门禁

- 不因联盟、球队或球员相关许可而自动认定竞品产品数据已获准使用。
- 没有竞品权利方针对精确数值、字段结构和再分发/改编的单独书面许可时，不得抓取、抄录、批量导入或以轻微扰动方式使用。
- 截图、视频、网页展示、玩家整理表、非官方接口或数据文件均只能作为待审核线索，不能直接成为发行数据源。
- 需要参考球员能力时，优先从获准官方统计、比赛表现证据和原创属性定义推演；记录公式、人工调整理由及版本差异。
- 仓库扫描发现竞品名称、来源 URL、数据字段或疑似逐项映射时，发行流水线应失败并要求数据审核。

### 4.2 38 项属性的来源记录

每名真人球员每个赛季至少保留：

- `player_id`、显示名版本、球队版本和数据生效日。
- 38 项字段定义与取值范围。
- 每项输入证据、允许使用的统计来源和数据时间窗。
- 原创归一化公式、位置修正、角色修正和上下限。
- 人工调整值、理由、调整人、复核人和时间。
- 与上一版本差异、异常值说明及固定种子模拟结果。
- 最终状态；任一输入来源为 `BLOCKED` 时，该真人数据包整体不得发布。

## 6. 自动化门禁建议

- `rights-lint`：校验台账必填字段、状态和到期日，任何未知 `asset_id` 失败。
- `content-scan`：扫描发行包中的禁用联盟字样、竞品名、未批准昵称和内部研究路径。
- `asset-manifest-check`：对图片、字体和音频计算哈希，只允许 `APPROVED_RELEASE` 白名单进入发行包。
- `data-lineage-check`：每个真人属性包必须指向来源版本、生成规则和审核记录。
- `expiry-check`：构建日期超出许可期限或平台/地区不匹配时失败。
- `release-snapshot`：每个候选版本固化台账、数据清单、素材清单、扫描报告和审核签名。

## 7. 发布前签核

- 产品负责人确认实际展示与 `intended_use` 一致。
- 数据负责人确认名单、统计和 38 项属性均可追溯，且没有竞品精确数值流入。
- 美术与音频负责人确认文件哈希和许可证一致，没有 Logo、官方球衣图案或未批准素材。
- 品牌/权利审核确认书面文件覆盖目标平台、地区、期限和营销用途。
- 工程负责人确认所有门禁通过，客户端不包含研究原始文件、许可文件或被阻止数据。
- 任一签核缺失时，不得把状态改为 `APPROVED_RELEASE`。

当前实现进度：音频清单、许可字段、来源域、SHA-256 与 `dist/client` 最终音频文件集合已由 `check-game-content.mjs` 强制校验，并通过 `postbuild` 绑定到每次生产构建；图片、字体和其他数据包仍需继续扩展同一门禁。
